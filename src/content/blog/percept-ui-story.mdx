Building a component library sounds straightforward: make some React components, style them, publish to npm. Six months into building Percept UI, I can tell you it's anything but.

Here's everything I wish I'd known before starting.

## Why Build Another Component Library?

Honestly? I wanted to understand how the big ones work. shadcn/ui, Radix, Mantine — I used them every day but treated them like black boxes. Building my own forced me to think through the decisions they made and understand *why*.

The other reason: I wanted something specifically designed around Tailwind CSS v4 and the new React Server Component model. Most existing libraries still carry patterns from the class-component era.

## API Design Is Everything

The hardest decisions aren't technical — they're API design decisions.

**Compound components vs. monolithic props:**

```tsx
// Monolithic (easier to use, harder to extend)
<Select options={options} value={value} onChange={onChange} />

// Compound (more verbose, infinitely flexible)
<Select value={value} onChange={onChange}>
  <Select.Trigger />
  <Select.Content>
    {options.map(opt => <Select.Item key={opt.value} value={opt.value}>{opt.label}</Select.Item>)}
  </Select.Content>
</Select>
```

I went with compound components for most things. The initial DX is worse, but you never hit a wall when you need a custom rendering slot.

**Styling strategy — CVA over raw Tailwind strings:**

```ts
import { cva } from 'class-variance-authority'

const button = cva(
  'inline-flex items-center justify-center rounded-lg font-medium transition-colors',
  {
    variants: {
      variant: {
        default: 'bg-primary text-primary-foreground hover:bg-primary/90',
        outline: 'border border-input hover:bg-accent',
        ghost: 'hover:bg-accent hover:text-accent-foreground',
      },
      size: {
        sm: 'h-8 px-3 text-xs',
        md: 'h-10 px-4 text-sm',
        lg: 'h-12 px-6 text-base',
      },
    },
    defaultVariants: { variant: 'default', size: 'md' },
  }
)
```

CVA gives you variant-aware type safety. TypeScript will catch `variant="invalid"` at compile time, not runtime.

## The CLI Was a Turning Point

The biggest DX win wasn't the components themselves — it was the CLI.

```bash
npx percept-ui add button
npx percept-ui add card input select
npx percept-ui init
```

Instead of `npm install percept-ui` and importing from a package, users copy the source directly into their project. This means:

- No version conflicts
- Full customization — the component lives in *your* codebase
- No bundle size surprises

This is the same model shadcn uses, and it's the right call for utility-heavy component libraries.

Building the CLI required `commander.js`, `fs-extra`, and a careful approach to template rendering. The trickiest part was detecting whether the target project uses TypeScript and generating the right file extension.

## Publishing to npm

The publish workflow tripped me up more than expected:

```json
{
  "name": "percept-ui",
  "main": "./dist/cjs/index.js",
  "module": "./dist/esm/index.js",
  "types": "./dist/types/index.d.ts",
  "exports": {
    ".": {
      "import": "./dist/esm/index.js",
      "require": "./dist/cjs/index.js",
      "types": "./dist/types/index.d.ts"
    }
  }
}
```

Three things I got wrong initially:

1. **Missing `types` in exports** — TypeScript couldn't find the type declarations
2. **Bundling Tailwind classes** — the CSS didn't ship with the package because I was only bundling JS
3. **Peer deps vs dependencies** — React must be a peer dep, not a regular dep, or you'll get two React instances

## Growing the Community

Getting the first 10 GitHub stars felt impossible. What actually worked:

- **Posting in r/reactjs** with a demo — one post got 3k views and 40 stars in a week
- **Writing docs like you're talking to a junior dev** — the more obvious you make things, the more people actually use it
- **Responding to every issue within 24 hours** — early contributors notice this and stick around
- **Good README** — I rewrote mine four times before the contribution rate went up

What didn't work: posting in Discords, cold-messaging influencers, cross-posting to every platform at once.

## What I'd Do Differently

1. **Start with fewer components.** I shipped 30 components in v0.1. I should have shipped 5 and done them perfectly.
2. **Write the docs before the code.** If you can't explain how to use a component in simple prose, the API is wrong.
3. **Add Storybook earlier.** Visual regression testing would have caught a dozen subtle style bugs I only found when users reported them.

Building Percept UI taught me more about React internals than three years of using React did. If you're thinking about building your own library — do it. Even if nobody uses it, you'll come out a better engineer.
